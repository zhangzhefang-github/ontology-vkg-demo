# 批准以审批记录的结论为准

是否批准，看审批记录上的结论，不看决策记录的状态列。状态列可以由有更新权限的账号写错。任务表用外键指向审批记录，这只保证对应的审批记录还在，不能保证结论是批准。执行事务必须读到该审批记录，确认结论为批准，并且决策记录上的排他锁已经拿到，然后才插入任务。执行状态列仍用来防止重复执行。

决策过程数据放在 `decision_loop`。供应风险复核任务放在 `procurement`，因为它是业务数据。任务引用订单和事件。决策记录只保存订单编号和事件编号，不反过来限制业务表的变更。

Ontop 的 SELECT 只保留 Mapping 的三张源表：`supplier`、`purchase_order`、`supply_disruption_event`。库级 `procurement.*` 会让它读到任务表。Ontop 对 `decision_loop` 没有任何权限。应用账号不能删除数据，也不能写这三张源表。实现时要确认 Ontop 只靠这三张表的 SELECT 仍能完成启动。
